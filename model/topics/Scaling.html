Data Transformation: Scaling a feature


 (Reference: Link )

Across projects which are shared on Linkedin or Kaggle, the scaling of continuous data is perhaps the most prominent form of data-preprocessing on non-discrete variables within a dataset.

This is no bad thing, however, there is a noticeable trend that Students of Data Science and Machine Learning apply either Normalization or Standardization as methods of scaling without understanding why such transformation is important. In addition, there is a lack of emphasis placed on understanding those circumstances where Scaling not appropriate, or unnecessary.

Within this article, I aim to provide you with an understanding of:

  • Why Data-Scaling is important;
  • Circumstances where Data-Scaling should be applied, and when such a transform is unnecessary;
  • The most common approaches to Data-Scaling: Normalization and Standardization;
  • The implications of scaling numerical sets which contain outliers, and solutions to overcoming such a challenge.

Why Data-Scaling is a Valuable Transformation in Data Preprocessing

Data Preprocessing, Visualized. Source: https://www.wallstreetmojo.com/data-preprocessing/



Whether it be a task that requires you to use Supervised Machine Learning Algorithms or Unsupervised Algorithms, at some point, you will likely be working with a dataset that contains a set of continuous variables. In addition, it is possible that these features, when compared to one another, may exist on notably differing scales. To illustrate such a circumstance, let us take a hypothetical scenario:

Imagine you are working on a Supervised Learning problem, where you are attempting to predict a person’s health status. This hypothetical dataset consists of the following variables:

  • ‘Weight’ — Each Individual’s weight measured in Kilograms;
  • ‘Height’ — The height of each Participant, measured in Millimeters, strangely;
  • ‘Monthly Steps’ — The Person’s total number of recorded steps per month;
  • ‘Healthy’ —The encoded target variable, which we are tasked with predicting.


After an initial discovery phase where you gather descriptive statistics about the dataset, you find that the aforementioned continuous variables exist on widely differing scales:

A scenario such as this one can introduce challenges which cause issues when modelling, as a certain subset of Machine Learning Algorithms struggle to produce optimal results when fit to or trained on datasets that feature a wide spread of scales across input variables.

In such circumstances, you should apply Scaling methods in order to transform the dataset from one which contains continuous variables, each existing on their own unique scale, to a dataset where the continuous variables each exist on similar scales.

This transformation, when applied in the correct circumstances will likely increase the performance of your model, but there’s a catch.

Data-Scaling is Not Always Necessary

Scaling continuous features is a data-preprocessing step not explicit to Supervised Learning problems; this method of Data-Transformation is applicable to Unsupervised Machine Learning as well. Regardless, there are specific circumstances which you should be capable of recognizing that indicate the necessity of applying Scaling Transforms.

First, if the dataset contains features that exist on similar scales, you do not necessarily need to apply Scaling Transformations. However, in opposite circumstances, this is a first-indicator of a necessity to scale.

The next aspect to consider is the specific problem which you are trying to solve, and the algorithm(s) that you will be utilizing within your solution. In accompaniment with a set of features existing across notably varying scales, the following circumstances can be considered the confirming indicator that you will benefit from applying Scaling Transforms:

  • You are using a distance based classifier (SVM, KNNClassifier, etc.);
  • You are using a density or distance based unsupervised learning model to discover clusters and/or anomalies with your dataset (KNN, HDBScan, Local Outlier Factor, etc.);
  • You are using an algorithm that applies weighted sums to predict target variables (Linear Regression, Logistic Regression, Neural Networks, etc.).

On the contrary, it is not always the case that Data-Scaling is necessary when preprocessing; if you have a dataset which contains continuous features which exist across varying scales, but you will be employing tree-based algorithms in your solution (i.e., Decision Trees, Random Forest, Isolation Forest, GBDTs), it is unlikely that you will see as much benefit/increase in performance as those prior listed application and algorithm pairs.

Common Approaches to Data Scaling

Data-Scaling is typically achieved by applying either the ‘Normalization’ or ‘Standardization’ Data-Transforms. These are two different approaches, which both attempt to achieve the same goal: transform the raw data from its original scale to a more standard one.

Normalization

In its simplest form, the application of the Normalization algorithm will result in a raw set of numbers being transformed to a set of values which range between 0 and 1.

Normalizing a continuous feature involves the use of both lower and upper boundaries, which can be estimated using descriptive statistics (min, max) upon your current set of values, or by manual configuration based upon domain knowledge.

It should be noted, however, that in real world applications of Normalization, that it is entirely possible for future values to exceed the prior-configured upper and lower boundary values. In such cases, we will apply a capping operation on any exceeding values. This means that, if some new value ‘x’ exceeds the upper boundary, we will replace x with the pre-determined maximum acceptable value and vice versa for cases where x is less than the lower-boundary.

Normalization is easily applied using the functionality provided by the MinMaxScaler within the Scikit-Learn library.




Standardization

Standardization is the second-most common method applied when attempting to scale raw data from its original form to a more optimal one prior to modelling, and given the right conditions, it is a more ideal Scaling Transform.

Unlike Normalization, it is important to know that Standardization will make assumptions about your raw dataset:

  1. Your raw set of values display a Gaussian Distribution; and
  2. The Mean and Standard deviation are non-anomalous.

Following an initial exploration, you will discover whether your dataset displays such characteristics. If this is not the case, Standardization can still be applied but may not produce optimal results, therefore you may want to experiment with Normalizing the features instead, or applying Quantile or Power Transforms to mould your features to a state ideal for the application of the Standardization Algorithm.

It is essential knowledge that you understand how Standardization differs from Normalization in regards to how the statistics required for transformation are extracted/discovered:

  • In Normalization, it is acceptable to extract the minimum and maximum values using all data available to you.
  • Standardization requires that you extract the Mean and Standard Deviation specifically from your training set, rather than all available observations to prevent data-leakage.

Standardisation is easily applicable to your numerical sets by using the StandardScaler, provided within the scikit-learn library.

The Implications of Scaling on Data Containing Outliers

Within the realm of applied Machine Learning, an ‘outlier’ is a data-point within a larger set of values that exists at the fringes of the set’s distribution. An outlier does not accurately represent the numerical set in any fashion, and may exist in a relatively dispersed neighbourhood of values.

The presence of outliers within a dataset may negatively affect scaled transformations, and by extension, this negatively impacts the performance of any fit machine learning model. This is the case for both Normalization as well as Standardization, given that outlier observables within the set of values will skew the statistics necessary to perform scaling transformations:

  • Within Normalization, the minimum and/or maximum values may be skewed, thus affecting scaled transforms;
  • Similarly, the Standard Deviation and Mean values will be skewed, thus impacting Standardized transforms.

In order to overcome the challenges associated with scaling sets that contain outliers, you should apply ‘Robust Scaling’ — a modification of Standardization which substitutes those statistics which will be affected due to the presence of outliers:

  1. Mean is substituted with Median;
  2. Standard Deviation is substituted with the Interquartile Range.

Through the application of Robust Scaling, the resulting scaled data-transform is typically one which contains:

  • A Mean of zero;
  • A Median of zero;
  • A Standard Deviation of one.

Most importantly, the transformed set of values is not affected by outliers, which is the result of using descriptive statistics which are not skewed by anomalous data-points (IQR, Median), thus the benefits associated with Normalization and Standardization will be carried over to this transformed dataset which contains outliers.

Robust Scaling is easily achieved through using Scikit-Learn’s RobustScaler.

Conclusion

At this point, you have increased your capability to perform data-preprocessing with an understanding of why such Numerical Transforms are necessary, or beneficial (or not!). More specifically, you now ideally understand:

  • The benefits associated with Data Scaling, given the appropriate circumstances;
  • Aspects of a Data Science project which indicate the necessity of Data Scaling;
  • The two most common methods of Scaling Transforms: Normalization and Standardization.
  • The challenges introduced when Scaling on Datasets which contain outlier values, and how to overcome such challenges using the Robust Scaler.
